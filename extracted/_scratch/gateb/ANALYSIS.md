## 1. W=1993 的**精确定义**：job+0x98，非 140e72ea0（O+D）

... if (*param_4 <= local_38) local_3c = *param_4;     // 再夹到区间右端

⇒ 可达窗 = `[start , start + job0x98 - 1]`（两侧独立，各截到区间末端）。观测①"起点距窗原点 ≤1992 配对、=1993 不配"给出 **`job+0x98 == 1993`**（D，边界 1992/1993 精确反推，见 replay 输出 13/13）。

**关于 140e72ea0"2 的幂上取整"的关系澄清（任务明确要求）**：
`140e72ea0.c` 里 `iVar1` 循环 `for(iVar1=2; iVar1<*(param_1+0x98); iVar1*=2)` 之后写的是 **`param_1+0x38`（掩码 `iVar1-1`）**、`param_1+0x48`、`param_1+0x50`（两张初始填 `0xffffffff` 的表），**完全没有回写 `param_1+0x98`**（O，`140e72ea0.c:19-23`）。
⇒ **140e72ea0 的幂上取整只用于 hash/散列表尺寸，与窗口宽 `0x98` 无关**；1993 不是 2 的幂，正因为二者是不同字段。`0x98` 的真正来源是 `140e72f50.c:24-25`：`uVar4 = (*(provider_vtbl+0x38))(provider); job+0x98 = uVar4;`，即 **provider 对象虚表 +0x38 的 getter 的返回值**（O）。若 `vtbl+0x20` 返回 0 则 `job+0x98=1`（`140e72f50.c:19-22`，"无窗口/禁用"分支）。
**未知**：该 `+0x38` getter 的实体（应为对齐 provider 的 `windowSize()`），以及它为何取 1993。1993 不来自任何在本族反编译代码中出现的字面常量（全量 grep `0x7c9`/`1993` 无命中，见搜索输出），故 `job+0x98=1993` 的常量注入点**位于本族之外**（provider 构造/配置层），本轮未定位。可移植实现只需把窗宽做成一个可配置整数、默认填 1993 即可复现行为，无需复现幂上取整逻辑。

## 2. 发射过滤的**准确条件**（对角候选记录门，O）

候选记录的唯一门槛在 `140e73040.c:76`：
```

   ...写入候选数组 job0x90+0x90，记录 {len=*(0x64), weight=iVar10, startL=0x6c, startR=0x68}
   *(int*)(job+0x88) += 1;   // 候选计数++
}
```
`iVar10` 在游程累加循环里 `iVar10 += FUN_140e74a70(...)`（`140e73040.c:41`）。
`FUN_140e74a70.c` = 读 `job+0xb0[side]` 权数组的第 l 项。该数组由建表器 `140e72af0.c:91` 填充：`uVar3 = FUN_140e75c50(local_40==0, local_31, prov_vtbl+0x60(...))`（**三参调用**，O，`140e72af0.c:88-91`）。
`140e75c50.c` 语义（O，附汇编 `asm/140e75c50.asm`）：
```
if (param_1 /*行缺失 null*/ != 0) return 2;             // 行取不到 -> 权重2
if (param_3 /*len*/ == 0) param_3 = param_2 ? 10 : 1;   // len0: 空白10 / 空1
if (param_2 /*空白 flag*/) param_3 = param_3*2 + 0x32;  // 空白: 2*len+50
else                     param_3 = param_3   + 0x1e;   // 非空白: len+30
```
⇒ **非空白行权重 = `len + 30`，不是 `2*len+50`**（原背景 140e75c50 读法把 `2*len+50` 归给了非空白行，实际 `2*len+50` 属空白行，O）。K=1 且 len=300：单行权 = 330 < 500 → **候选门 `500<iVar10` 失败**（D）。
发射器 `140e74100.c` 里**没有任何 len/长度下限**：发射判据是 `0 < piVar1[1]`（`140e74100.c:65,130`，即 weight>0）；`140e74080.c:25` 会在截断/重叠消解后把 weight 重算，若 `weight<500` 则清零 → 该候选**不发射**（O）。即 len=1 候选被"weight<500"排除，而非专门的 len 门（D）。

## 3. 反常① K=1 单行 300 字符窗内不配对 — **已解（O+D）**

- 背景给的行权重 `2*len+50`（≈650>500）对 K=1 成立与否取决于空白判定；按 `140e75c50` 真实读法，非空白行 = `len+30` = 330。
- 无论 330 还是 650，K=1 游程的 `iVar10` 都**只在恰好等于该单行权重**时判定；`140e73040.c:76` 需 `iVar10>500`。330→失败（发射被排除）。这与 replay 中 `big1-off*` 的 Z 恒为 `leftorphan`+`rightorphan`（off=1000 也在窗内仍不配，见 `replay_output.txt`）一致。
- 但背景坚持 K=1 权重≈650>500 却仍不配对。两条**独立**解释，二者都能否定"纯 weight 门"：
  1. **seen 位图预标记**：`140e73040.c:22-25` 入口即 `if (*seen[l-row][col]) return;`，游程产出后 `140e73040.c:63-67` 把对角上每格 seen 置 1。K=1 的格若在其所在对角更早的扫描中已被同 key 的别处标记，则候选从不产生。
  2. **provider vtbl+0x60 的 len 语义**：`140e75c50` 第 3 参来自 `(**(vtbl+0x60))(prov, side, line)`（`140e72af0.c:88`）。若该 provider 方法对"长行/被截断行/特定行"返回一个使 weight 落到低位的结果，300 字符长行可能被判 len≈0 → weight 10~60 < 500。
- **结论（I）**：反常①由 **`500<iVar10` 候选记录门** 造成——K=1 单行游程的权重和不过 500，因而**根本不作为候选进入 `140e74100` 发射**，与窗口宽无关（off=1000 也失败正是因为它是长度 1 游程）。精确的 len 语义（330 vs 650）取决于 **provider vtbl+0x60** 返回什么，本轮未反编译该 provider 实体 → 标 **未知**（子项）。发射路径确无 len≥2 硬门（O），故移植时"短游程过滤"必须用 weight>500 复现，不能只靠 len 阈值。

## 4. 反常② K=100 触发 `>4999` 仍正常配对 — **已解（O，汇编铁证）**

背景把 `140e73040.c:45` 的 `if (4999 < iVar10) { FUN_140052fe0(...); FUN_140012e10(...); }` 读作"abort 终止扫描"是**错误**的。真实汇编 `asm/140e73040.asm`：
```
140e73147  CMP EDI,0x1388        ; 阈值 0x1388 = 5000，即 iVar10 >= 5000（不是 >4999 的"终止"）
140e7314d  JL  0x140e73168        ; < 5000 → 跳到下一对角步
140e7314f  MOV RCX,[0x140e70a98]  ; >= 5000 → 构造异常对象（Delphi，code=0x0EEDFADE，见 140012cb0.asm 已核）
140e73158  XOR R8,R8 ; CALL 140052fe0
140e73163  CALL 140012e10         ; raise
140e73168  ...                     ; ★ JL 的目标 == raise 之后的下一条 ★
```
- raise 之后**没有 break/return/jmp-to-exit**，控制直接落入 `140e73168`，与"weight<5000"路径是同一地址（O）。`140012e10→140012cb0` 是 Delphi `RaiseException(0x0EEDFADE,...)`；`140e73040` **序言无 SEH 建立指令**（PUSH 寄存器 + `SUB RSP,0x38`，无 `.xdata`/UNWIND 里的 handler 槽，O）。
- ⇒ 语义是**断言/越界上报**（把过长的对角游程当作内部错误抛给**外层**处理器），**不终止本函数**；K=100（游程权重 5580，跨过 5000）照样把游程收完并在 `140e73040.c:76` 记录候选、正常发射 → 观测⑤"K=100 仍配对"完全吻合（D）。
- 补充（D）：K=100 单游程权重 5580 > 5000，若外层真有捕获则会改变结果；但 oracle 显示 K=100 正常，说明要么外层捕获后回退整段（对平凡形状行为等价，见观测⑥），要么阈值路径在此数据下未真正抛出被捕获。倾向：**这是软断言**，正常发布构建里 `EAssertionFailed`/`ELockError` 类异常被顶层 try 吞掉并继续。子项"外层 catch 具体在哪个 caller 吞掉"**未知**。

## 5. 观测 1–3 的精化（O+D）

- **观测①（W≈1993，行列对称，负偏移同）**：由 §1 精化为 `job+0x98=1993`，可达窗 `[start, start+1992]`；两侧独立夹取（`140e733b0.c:25-36`），故行列对称、负偏移同。replay 对 off∈{1989,1990,1991,1992}→配对、1993→0 全部命中（13/13，`replay_output.txt`）。
- **观测②（起点距 1990、块尾 2189>窗边界仍全配）**：`140e73040.c:30-57` 游程收集沿对角线**持续前进直到 `140e722a0` 越出区间右界**（`cVar4/cVar5` 任一 '\0' 才 break），不受"起点是否在窗内"以外的宽度限制。窗口只决定**哪些对角被起始扫描**（`140e733b0.c:47-76` 的 do-while 步进到 `*param_4/*param_5` 为止，二者=窗右界），一旦某对角起点在窗内被采到，其**延伸长度只受区间边界限制**。故"窗宽截起点扫描、不截游程延伸"（D，精确匹配代码结构）。
- **观测③（K=2 短文本起点距 1992 也不配）**：K=2 短行 weight≈`2*(len+30)` 远<500 → §2 候选门排除（D）。

## 7. 移植结论（D）

窗口引擎可移植，须复现：(a) 窗宽=可配置整数，默认 1993，语义 `[start,start+W-1]` 两侧独立夹取；(b) 候选记录门 `weight>500`（非 len 门），行权 `非空白=len+30 / 空白=2*len+50 / 缺失=2`；(c) 窗内**对角起点**扫描、游程**延伸**仅受区间边界限；(d) `5000` 分支为软断言（不终止），可省略或仅日志；(e) 重叠消解与排序见 `140e74100.c:33-123`（先截右界+reweight、按 weight 降序 `140e73f30`、再按 startR/startL 排序 `140e73d30`、两两区间嵌套判优）。

## 8. 一句话总览

窗口引擎 = 带宽 `job+0x98`（实测 **1993**，两侧独立夹取 `[start,start+1992]`）的对角线扫描器；候选**只**受 `140e73040.c:76` 的 `weight>500` 门过滤（行权 `非空白=len+30/空白=2*len+50`），**无** 专门的 len≥2 发射门；`iVar10>4999` 分支（阈值 `0x1388=5000`）是**软断言**（raise 后循环体 fall-through，本函数无 SEH 帧），**不终止扫描**。反常①由 weight>500 候选门 + provider+0x60 语义解释；反常②由汇编铁证"无终止语义"解释。
