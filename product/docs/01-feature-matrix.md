## 2. 逐功能详表

### 功能 1 — 双文件文本比较

| 项 | 内容 |
|---|---|
| **用户流程** | 指定左右两个文件 → 系统按内容类型选引擎 → 逐行对齐 → 标注 same/similar/different/orphan → 输出可视化或报告 |
| **输入** | 两个文件路径；可选：比较规则（大小写/空白/行尾）、重要性设置、过滤器、对齐规则 |
| **输出** | 对齐结果（每行的状态 + 左右行号）；6 种文本报告布局；退出码（0=同, 1=异, 2=错） |
| **参考证据** | `verify/golden/` 45 锚点（**O**，status 序列对 5.2.1 亦成立，见 02 §3.4）；`verify/layouts/` 30 布局（**O**，数据体成立）；`clone/` 661 行实现（**O**，45/45 + 29/30）；`report-algorithm.md` Myers 结构（**O**）；`help/sessiontext*.html`（**O**） |
| **难度** | **中**。算法骨架已验证；难点在**重要性引擎**的完整语义 |
| **依赖** | 行切分/编码；对齐；重要性；报告输出 |
| **验收测试** | ① `bcx-verify.py` 45/45 status ② `bcx-layout-verify.py` ≥29/30 ③ 扩充锚点至 ≥80 例仍全绿 |
| **状态** | **原型**（规格级，非产品级） |
| **缺口** | 真正的语法分词器；逐元素重要性（`CaseSig`/`Weights`/强制重要元素）；大文件性能；编码探测级联的完整实现 |

**已知未覆盖**：`clone/README.md` 声称的"全空白忽略（含标点邻接）"经源码核对属**归一化层面的近似**（`norm()` 直接删除所有空白），不是 BC 的逐元素语法规则。这对 `f( a )` vs `f(a)` 类用例结果相同，但对"字符串内空白"等场景**可能不同**——须扩锚点验证（U1）。

### 功能 3 — 文件夹比较

| 项 | 内容 |
|---|---|
| **用户流程** | 指定左右两个目录 → 按判据（默认时间戳+大小）比对 → 标注 same/diff/ltonly/rtonly/newer/older → 可下钻到文件级比较 |
| **输入** | 两个目录；criteria（size/CRC/binary/rules-based/timestamp/attrib/version/owner/group/permissions）；过滤器；子目录展开策略 |
| **输出** | 目录树状态；`folder-report`（side-by-side/summary/xml） |
| **参考证据** | **本次审计实测**（**O**）：① Oracle 配方 `load` + `expand all` + `folder-report`（修复了 exit 106 的旧脚本）② 判据模型：默认 size+timestamp 判 `same`，`criteria CRC/binary/rules-based` 判 `diff` ③ 状态词表：`same`/`diff`/`ltonly`/`rtonly`；`help/scripting_reference.html` FOLDER-REPORT/CRITERIA（**O**）；`specs/dir/` 8 单元 + `Op\` 5 单元（**D**）；`extracted/` 中 `DirDiff`/`DirNewer`/`DirOlder`/`DirOrphan`/`DirHollow`/`DirFiltered` 状态串（**D**） |
| **难度** | **中**（只读比较）；**高**（含文件操作） |
| **依赖** | 文件系统抽象；判据引擎；递归遍历；过滤器 |
| **验收测试** | 扩展 `verify/dir/trees` 夹具至 ≥40 例，覆盖：空目录、仅左/右、大小同内容异、时间戳容差、属性差异、符号链接、深层嵌套；对拍 `folder-report layout:xml` |
| **状态** | **未开始**，但**规格已就绪**（本次审计补齐了配方与判据） |
| **注意** | 现有夹具**只覆盖 3 种状态**（same/diff/ltonly/rtonly），`newer`/`older` 等**未覆盖**——须扩夹具 |

| 项 | 内容 |
|---|---|
| **用户流程** | 选方向（左→右/右→左/双向）→ 预览将执行的操作 → 确认 → 执行复制/删除 → 报告 |
| **输入** | 两侧目录；同步方向；冲突策略；过滤器；dry-run 开关 |

| **难度** | **高**。**这是唯一会破坏用户数据的模块**，风险等级最高 |
| **依赖** | 功能 3；事务性文件操作；冲突检测 |
| **验收测试** | 必须包含**破坏性测试**：中断恢复、部分失败回滚、只读文件、长路径、权限拒绝 |

| **建议** | ~~不纳入 MVP~~ → 已纳入；残留的安全设计评审需求收窄为"范围声明"里的未实现项 |

### 功能 6 — 表格/CSV 比较

| 项 | 内容 |
|---|---|
| **用户流程** | 指定两个表格（CSV/XLS/XLSX/HTML）→ 解析为行列模型 → 按列类型对齐 → 标注单元格/行/列差异 |
| **输入** | 两个表格文件；列类型；分隔符；表头行数；多工作表选择 |
| **输出** | 单元格级差异；`table-report` |
| **参考证据** | `help/commands_table`/`sessiontable*.html`（**O**，语义）；`extracted` 中 `TableMap`/`TableDetect`/`TableRules`（**I**）；`bcfileformats-spec.json` 含表格格式定义（**D**） |
| **难度** | **高**。难点是**行匹配算法**（非行号对齐，而是按键/相似度配对）+ Excel 格式解析 |
| **依赖** | 表格解析（CSV 自研；XLSX 需库）；行匹配算法 |
| **验收测试** | CSV 子集 ≥30 例对拍 `table-report`；XLSX 另立里程碑 |
| **状态** | **CSV 子集收口（2026-10-18，M6.4 + m67/m68，docs/13 §6–§9）**：core/table.rs 三态格式（.csv 固定逗号 / 联合检测 逗号>tab>分号>管道 / rawline 回退）+ CLI data-report/table-report + 帧全量比较。验收：全帧重放 **175/0（+12 空格 KNOWN 报告 / 2 skip）**、官方门禁 **819/819**（含 `table` 套件 19 判别细胞 × oracle/双安装/candidate，m68 收编混合扩展名 pin + interleaved rawline）。空格分隔切分定案为永久 KNOWN：m67 第七批探针把矛盾钉在 Oracle 自身渲染（H5：两侧首行逐字节相同仍 `<>`，§8），产品维持 rawline 回退；XLSX/HTML/列类型推断仍未实装 |
| **注意** | BC 用商业组件 FlexCel 解析 Excel。**自研 XLSX 支持工作量巨大**，建议 MVP 只做 CSV/TSV，XLSX 单列里程碑 |

## 3. 功能间依赖图

```
                    ┌─────────────────┐
                    │ 核心：字节/文本  │
                    │ 抽象 + 对齐框架  │
                    └────────┬────────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
   ┌────▼─────┐        ┌─────▼──────┐      ┌──────▼──────┐
   │ 文本比较  │        │ 文件夹比较  │      │  二进制比较  │
   │ 功能 1 ✅ │        │ 功能 3     │      │  功能 5 ✅  │
   └────┬─────┘        └─────┬──────┘      └──────┬──────┘
        │                    │                    │
   ┌────▼─────┐        ┌─────▼──────┐      ┌──────▼──────┐
   │ 三方合并  │        │ 同步/复制   │      │  表格/图片   │
   │ 功能 2   │        │ 功能 4 ✅  │      │ 功能 6 ✅/7 ✅│
   └──────────┘        └────────────┘      └─────────────┘
                             │
                    ┌────────▼────────┐
                    │ VFS 抽象层       │  ← 架构关键点
                    │ 功能 9/10       │
                    └─────────────────┘

  横切能力：报告(11) / 会话(12) / 脚本(13) / 集成(14) / 规则(15) / GUI(16)
```

**架构含义**：所有引擎共享**同一套对齐框架 + 同一套差异映射抽象**（`*Map` 模式）。这是 BC 能在 9 种内容类型上统一展示的原因（**I 级推断**，但由 `TextMap`/`TableMap`/`PixMap`/`HexMap`/`RegMap` 命名一致性支撑）。**本项目的架构必须复制这一模式，否则会退化成 9 个独立工具。**

## 6. 明确不做的事（边界）

1. **不复制** BC 的源码、二进制、位图/主题资源、`.tr` 翻译文件、`BCFILEFORMATS.xml` 原文。
   - `BCFILEFORMATS.xml` 是**行为规格数据**（格式名、元素类型、关键字表）——可用于**指导自研词法规则**，但**不得原样打包分发**。
2. **不声称** 1:1 复刻。目标是**行为兼容的可验证子集**。
3. **不实现** 绕过授权、破解、试用期规避。
4. **不修改** 现有 `clone/`、`verify/`、`extracted/`、`ghidra-project/`、`report-*.md`。
5. **不把** 反编译伪代码当作原源码。
