# 20 — 产品方向定案：能力全继承，界面自设计（2026-10-22 用户批准）

> 本文取代"逐像素 1:1 复刻"路线，成为 **LiuCompare** 的设计权威。
> 1:1 侦察阶段（docs/19）的全部实测成果**归档为参考证据**，一行不浪费。

## 0. 决策原文（用户，2026-10-22）

> 不做 1:1 完全一样的产品，而是参考 BCompare 的界面布局、功能和体验交互，
> 产出我们自己的产品。BCompare 的能力都是需要的——核心内容、功能、交互、
> 功能能力都要；界面设计和布局可以拿他的理解和参考怎么设计的，
> 毕竟他是做了很久的产品。

拆解成两轴判据：

| 轴 | 判据 | 依据 |
|---|---|---|
| **能力轴**（功能、交互语义、行为规则） | **全量继承 BC** | BC 从 1996 年迭代至今，其功能集=千万用户验证过的需求规格；照单继承是最便宜的产品定义 |
| **表现轴**（像素、位图、色号、控件皮肤、图标） | **自主设计**，以 BC 的布局为参考 | 像素级复刻的边际价值≈0（用户不感知 3/255 色调差、hatch 相位），且会继承 VCL 时代的历史债（字体渲染、DPI、废弃布局） |

## 2. 从 1:1 侦察继承的资产（参考证据库）

这些是花真金白银探针换来的知识，**转为本产品的行为规格**：

- **视图分派规则**（§6.9）：按扩展名路由、`.reg`→Text（实测≠帮助文档）、未知兜底 Text、
  六视图 task-only 无文件路由。→ 直接作为我们 GUI 的行为规格（语义层，keep）。
- **窗口标题格式** `{L} <--> {R} - {View} - Beyond Compare`：语义（双路径+视图名标识）保留；
  品牌后缀改为 `- LiuCompare`（表现层，reimagine；D1 已定）。
- **窗格内容不进 UIA**（BC 实测）：**我们决定推翻**——自家产品把行内容暴露给无障碍树
  （accessibility 反超 BC，§6.11 决策项 D3）。
- **灰态双层模型**（§6.6）：视图能力掩码 + 会话状态谓词——这个**架构**保留（它是正确的
  菜单状态管理设计），具体菜单树换成自家的。
- **display 模式语义**（§6.11）：All/Diffs/Same 互斥单选 + tooltip 即模式描述 + footer
  `行:列`=源位置——语义 keep，控件皮肤（flat toolbar）reimagine。
- **211 DFM / 四矩阵 / chrome+骨架快照**：降级为**布局参考库**——想知道 BC 把什么放在
  哪里（菜单归类、工具栏分组、窗格布局），查它；不再要求逐字节一致。
- **引擎契约**（BC 兼容 XML/退出码/脚本语法）：从"验收纪律"升级为**产品特性**——
  BC 用户的脚本与工作流可直接迁移（docs/19 §2.2 的字节级判定继续适用，且不再需要
  与 Oracle 逐格对拍新通道，除非我们主动选择跟进）。

## 3. 表现轴：我们的设计基线（与 BC 的差异 = 卖点清单）

| # | 项 | BC 现状 | 我们 | 理由 |
|---|---|---|---|---|
| P1 | 控件渲染 | VCL owner-draw，非原生 | WPF 原生主题感（Fluent 基础） | 现代观感，用户第一印象 |
| P2 | 高 DPI | BC 弱项 | 全程 DIP+per-monitor v2 | 1:1 路线下这是无底洞；自设计一举解决 |
| P3 | 图标 | 不可复制（版权）+ 位图老旧 | 矢量自绘/开源图标集 | 版权禁区本来就必须自设计 |
| P4 | 字体 | BC 固定字体栈 | 可配置（默认 Cascadia/Consolas），行距随字号 | 开发者产品的核心体验 |
| P5 | diff 配色 | 淡红/淡蓝底+对角点阵 | **色相语义保留**（红=差异、蓝=相似、点阵=空侧），明度/饱和度可优化对比度 | WCAG 对比度可反超 BC；实测色号归档为参考 |
| P6 | 无障碍 | 窗格内容不进 UIA | 全内容+状态进 UIA | **D3 已定（不藏）**；控件选型=自绘+UIA Text/Grid provider |
| P7 | 快捷键 | BC 体系（Alt+← 等） | **键位语义继承 BC**（肌肉记忆是能力的一部分），可增不可无故改 | 能力轴与表现轴的分界示例 |

**菜单/视图结构决策（2026-10-22 校准）**：用户定"能力全要"——16 功能全部在
产品范围内，因此 **12 视图与菜单树作为能力结构整体继承**（不裁剪）；"按自家
backlog 重新组织"仅适用于**未来**出现 BC 没有而我们要加的功能（如 git 面板）时
在既有结构上扩展，而非删减。§6-3 原"菜单树按 MVP backlog 重组→docs/21"作废
（docs/21 不再需要：结构=继承，表现=自家渲染，无中间设计稿）。
**界面布局总纲**：双栏窗格 + 底部详情条 + **左缘竖条 overview**（2026-10-22
活体实测修正：BC 的 TUiThumbnail 在 x=34 左缘全高竖条，非"底部行距缩略图"；
docs/19 §6.12-B）+ 顶部菜单/工具栏的五区格局照参考 BC（这套布局是被验证的
空间模型）；工具栏按钮集合、菜单树**结构整体
继承 12 视图**（见上：能力全要不裁剪），自家渲染（皮肤/字体/配色=自家）。

## 4. 验收判据的更替（防止"快→散"）

1:1 的隐性优点是完成有客观判据。新路线**必须同时**立起新硬判据，缺一即烂尾：

1. **语义门禁（keep）**：引擎字节级门禁全套保留（reacmp 自身）；分派表/灰态双层/radio
   互斥等行为规格 → 转写为**自家回归断言**（不依赖 Oracle 启动）。
2. **结构门禁（换代）**：UIA 树快照从"对 Oracle"改为"对**自家 golden**"——首轮以现有
   211/290/410 管线自动生成自家基线，此后改动必须显式更新基线（同 git snapshot 纪律）。
3. **视觉门禁（换代）**：PrintWindow 截图基线 = 自家批准样张（含暗色/亮色/高 DPI 三套），
   像素比对仅对自家基线，负向验证方法保留。
4. **体验对标（低频）**：每里程碑一次"BC vs 我们"人工走查（用探针基建做对照截图，
   语义差异记录进本文修订），不再逐钮取证。

## 5. 决策记录（2026-10-22 用户拍板）

- **D1 品牌 = LiuCompare（定）**：窗口标题、关于、设置/数据目录、安装包名统一
  **LiuCompare**。窗口标题模板 `{L} <--> {R} - {View} - LiuCompare`（结构继承 BC 实测的
  `{L} <--> {R} - {View} - <产品名>`，仅品牌后缀替换）。BC 字样仅出现在兼容选项里
  （如"兼容 Beyond Compare 脚本/XML"）。引擎二进制沿用 `reacmp`/`reacmp-gui`（CLI
  已收口的 BC 兼容契约、脚本、退出码、golden 全部不动），产品对外名 = LiuCompare；
  如需统一 CLI 二进制名另列后续项（不在 MVP 关键路径，改名会牵动全部引擎门禁）。
- **D2 窗口尺寸/默认布局 = 跟 BC 一致（定）**：默认尺寸与 BC 实测会话窗口一致
  （1456×864，参考 `gui-text-session-en.json` TViewForm rect），记住上次尺寸/位置。
- **D3 无障碍 = 不藏，全内容进 UIA（定）**：实测 BC 故意把窗格代码行文字对读屏
  软件隐藏（TTextEditor 的 UIA 子节点只有滚动条/状态栏，无行内容）。**我们主动推翻
  这个选择**——行内容、行状态（same/different/…）、行号全部暴露给辅助功能树，
  读屏器可逐行读出、自动化测试可读。影响窗格控件选型：保留自绘，但额外提供 UIA
  provider（TextPattern + GridPattern）而非裸 peer=null。这是反超 BC 的卖点。
  **落地（2026-10-22，第四步）**：TextPaneView 加 UIA peer——Group(TextPane)
  每行一个 Text 子节点，name=`{行号} {状态}: {文本}`（空侧=`(empty)`），
  默认 ON/`REACMP_D3=0` 退路。**关键实测**：WPF 的 UIA 桥根本不对
  IsControlElement=false 的 peer 暴露节点（探针实锤）——行改走控制元素，
  结构门禁在共享遍历器按 class `TextPane` 显式豁免子树（骨架/chrome 基线
  不破，已活体验证 24 节点全等）。新活体门禁 `uia-d3-check.py`：骨架不泄漏
  + 双窗格 2×12 行逐行 name==引擎台账；负向（D3 关闭→行消失被抓）。
- **D4 文本合并 = P1 首位（定）**：不进 MVP 关键路径（引擎未实现，先探测老纪律），
  但紧随 MVP 第一个做。
- **D5 暗色主题 = MVP 就带（定）**：自设计红利，亮/暗双主题基线随窗口壳一起做。
  **落地（2026-10-22）**：`product/gui/themes/{light,dark}.json` + `--theme` 接线
  （Theme.cs 叠加式覆盖：light 文件零色键=实测源原样、行为逐字节不变已用 ledger
  等价证明；未知主题名退 4 不静默兜底）。dark 色板=自家设计、色相语义保留
  （§3 P5：红=差异/蓝=相似/点阵=空侧），每色在 dark.json 内注明设计规则与
  WCAG 对比数（ink 12.9/10.2:1、digits 4.8:1、tint 上 ink ≥8.3:1）；几何不主题化
  （沿用实测格架=布局参考）。活体门禁 `tools/theme-dark-check.py`（期望值读
  dark.json 声明数字，非自引用）正向 10 tint+gutter+radio 全绿、负向（变异色板
  注入产品）2 违例被抓=可红证明。暗色第一档范围=窗格+过滤条+窗口底色；
  菜单/工具栏/Dialog 全量皮肤（§3 P1 Fluent 皮肤）=后续项。
- **D6 git 集成 = MVP 只读（定）**：MVP 只读（从 git ref 拉版本作比较输入，不写）；
  stage/commit 等可写操作排 P1+，先过安全设计评审。
