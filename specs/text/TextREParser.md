## 1. 引擎结构

### 1.1 字符类节点（已在前序会话定性）— `FUN_1410034d0(parser, ...)`
节点类型分派（读 **WideChar** 前瞻，2 字节步进）：
- `0x28 '('` → 子表达式（FUN_141003a50），要求闭合 `0x29 ')'`（否则报错，消息 @1410038e0）
- `0x2e '.'` → **任意字符**；有字符集对象（+0xc0）时按其允许集，否则用 **SsClasses 空字符集占位**（FUN_140528010 + FUN_141006fb0）
- `0x5b '['` → 字符类（FUN_141002f50 解析字符集；构造/校验）
- 其他 → 字面（FUN_141002ee0 解析）
- 尾部 FUN_141003300 收尾；分类查表 DAT_1410038e4（与 SsClasses 的 IsInlineWhitespace 表同构的 256 位表）

### 1.2 执行器（~~NFA 步进~~ → **DFA 编译 + 最左最长匹配**）— `FUN_141003e70`（4835B，全单元最大）
> **⚠ 二遍修正（见 2.6）**：本节第一遍结论有两处错误。(a) 0x10/0x20/0x14/0x18/0x24 **不是"指令步长"而是字段偏移**，真实记录步长为 0x28/0x30/0x18/0x08/0x118。(b) **没有回溯栈**；`141003e70` 是**编译入口**（构造 DFA + 最小化 + 落转移表），运行期匹配在 `FUN_141002300`。

### 1.3 位置集计算 — `FUN_141005410`（1626B）
> **⚠ 二遍修正**：不是"匹配状态对象"。它是**firstpos/lastpos/nullable 计算**（Glushkov 位置自动机）：`param_3` = firstpos 集合、`param_4` = lastpos 集合、`param_5`(out) = nullable。按节点表（`param_1+0x78`）的 opcode 递归。详见 2.6.3。

### 1.4 辅助 — `FUN_141006610`（970B）
偏移 0x10/0x18/0x28 密集；**把节点表的一段编译成 0x28 指令段**（含字符集归并 `FUN_141006500`）。详见 2.6.2/2.6.4。

## 2.6 二遍：执行器指令集（子代理分析）

> 2026-10-13，纯语料精读（未使用 REA/MCP、未联网）。核心结论：**第一遍把 0x10/0x20/0x14/0x18/0x24 当作"指令步长"是误读——它们是字段偏移**。真实存在 5 种不同步长的记录数组（见 2.6.1）。

### 2.6.4 DFA 状态记录（0x18 = 24B）与执行器五阶段

| `+0x04` | 4B | **后继状态号**（本表内索引；行 332-333 写入，行 402-404 在归并阶段重写） |
| `+0x08` | 8B | 该状态的 **0x28 指令索引列表**（字符串数组，长度头在 `-8`） |

1. **行 101-135**：逐条模式串调 `FUN_141003ad0` 解析/编译进 `local_50`（0x30 数组）与 `local_60`（0x28 节点表）；`FUN_141005da0(local_50,0)` / `(…,1)` 取**两个根**（内联 `+0x10` / `+0x1c`）压入 `local_58`。

### 2.6.5 匹配策略：**惰性 DFA + 候选栈（最左最长）**，非回溯

- `FUN_141002300` = **模拟/搜索驱动**（语料内无调用者，属内部核心）。断言 **`TextREParser.pas 0x27b`**（`FUN_140016660(&DAT_141002540, *(param_1+8), 1) != 0`，输入串类型/编码检查）。
  - 输入串在 `+0x08`（UTF-16，长度在 `-4`），当前起点 `+0x14`，输出 `+0x10` = 命中状态、`+0x18` = 匹配长度。
  - 起点从 `+0x14` 起**递增**（最左优先）；每次尝试内用 `FUN_141001ee0` **逐字符确定转移**（原地改写状态），同时把沿途候选状态压入 `+0x20` 栈，并在 `+0x28` 数组按状态记录 `当前位置 - 起点`（= 已匹配长度）。
  - 撞到哨兵 `0x0d` 结束（`if ((short)ch == 0xd) break;`），然后弹栈**丢弃长度为 0 的候选**，取最长者返回 → **最左最长（POSIX 风格）**；否则起点 +1 重试。
  - 注意：`FUN_141001ee0` 在反编译中被标为 `void` 却被当布尔用（`while (cVar1 != '\0')`），**内层循环的精确终止谓词 `[?]`**。

### 2.6.10 性能特征（修正第一遍猜测）

- **匹配是 O(n×m)**（最坏：每个起点重跑一次 DFA），**非回溯、栈深有界**（候选栈深度 ≤ 接受状态数）。无灾难性回溯风险。
- 编译期有 **DFA 最小化**（阶段 3，两两比较 + 不动点循环，最坏 O(状态数³)），但只在模式列表变更时发生一次，且有哈希缓存（2.6.9）。
- ASCII 有 **O(1) 数组转移**（0x118 记录 `+0x10`），非 ASCII 走哈希映射（`+0x110`）→ 常见纯 ASCII 场景下转移为常数时间。
