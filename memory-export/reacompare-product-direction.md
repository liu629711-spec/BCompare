**Why:** pixel-1:1 cost scales linearly with UI surface while its user value decays to zero fast (nobody perceives a 3/255 tint difference or hatch phase), whereas the capability set is exactly the expensive-to-rediscover part; and "no hard acceptance criterion" projects go limp, so the pivot was shipped WITH replacement criteria, not just removal.

**How to apply:** before any GUI/design work read docs/20 first; when unsure whether something is capability or presentation, classify against the two axes — capability must match BC's measured behavior, presentation may (and should) be redesigned; never build a new gate that launches the Oracle for GUI pixels; engine work keeps full byte-level discipline.
